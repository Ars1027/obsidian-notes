一句话区分：保留站（Reservation Station，RS）负责让指令能够乱序执行，ROB（Reorder Buffer，重排序缓冲区）负责让执行完的指令按原来的顺序提交。

它们都是动态流水线中的硬件结构，但解决的是两个不同的问题。

### 1\. 先用一个例子理解

假设 CPU 收到三条指令：

```asm
I1: DIV F0, F1, F2    ; 除法，需要10个周期
I2: ADD F3, F4, F5    ; 加法，需要2个周期
I3: SUB F6, F7, F8    ; 减法，需要2个周期
```

三条指令互不依赖。

如果严格按照程序顺序执行，I2 和 I3 可能得等 I1 执行完才能继续，浪费时间。

动态流水线的解决方式是：

* 保留站 RS：让 I2、I3 不必等待 I1，可以提前执行。

* ROB：即使 I2、I3 先完成，也不能先正式提交，必须按照 I1 → I2 → I3 的顺序提交。

### 2\. 两者在 CPU 中如何配合？

简化示意：发射时，指令同时获得保留站和 ROB 项；执行完后将结果写入 ROB，之后按顺序提交。

可以把它们类比成：

* RS = 厨房工作台：哪个订单的材料先准备好，就先做哪个，不一定按接单顺序做。

* ROB = 按订单编号排列的交付清单：菜可以先做好，但最终必须按照要求的顺序正式交付。

### 3\. 具体区别

| 对比   | 保留站 RS         | ROB                |
| ---- | -------------- | ------------------ |
| 核心任务 | 调度指令执行         | 管理指令提交             |
| 保存什么 | 操作类型、源操作数或依赖标记 | 执行结果、目标位置、完成及异常状态等 |
| 顺序   | 允许乱序执行         | 按程序顺序提交            |
| 何时释放 | 通常在结果写回后       | 指令提交后              |
| 解决问题 | 数据等待、流水线阻塞     | 精确例外、乱序结果的有序提交     |

### 4\. 为什么有了保留站，还需要 ROB？

假设：

指令执行和提交时间示例

| 指令    | 执行完成   | 正式提交   |
| ----- | ------ | ------ |
| I1 除法 | 第 10 拍 | 第 10 拍 |
| I2 加法 | 第 2 拍  | 第 11 拍 |
| I3 减法 | 第 3 拍  | 第 12 拍 |

仅用于理解顺序的简化例子，假设每周期最多提交一条指令。

假设 I2、I3 已经执行完并直接修改寄存器，但 I1 在第 10 拍发生了异常。

这时 CPU 就遇到问题了：程序执行到 I1 出错时，后面的 I2、I3 本来不应该已经修改机器的正式状态。

因此引入 ROB：

* I2、I3 可以提前执行，把结果临时存在 ROB。

* ROB 等待排在前面的 I1。

* 如果 I1 正常完成，就按顺序提交。

* 如果 I1 发生异常，就取消 I1 及其后面尚未提交的指令，恢复精确的程序状态。

这就是课件里说的精确例外（Precise Exception）。

### 5\. 一个很容易混淆的细节

你在 Tomasulo 算法中会看到，保留站有 `Qj、Qk、Vj、Vk`，ROB 又可以保存结果。是不是功能重复了？

其实不重复：

* `Vj、Vk`：指令执行需要的输入值。

* `Qj、Qk`：输入还没准备好时，记录应该等待谁的结果。

* ROB：主要记录每条指令的输出结果及提交状态。

原始 Tomasulo 设计可以用保留站编号作为等待结果的标记；加入 ROB 后，课件采用 ROB 编号作为重命名标记。因此看到 `Qj = 3` 时，要结合具体结构，判断它代表 3 号保留站还是 3 号 ROB 项。

最后记住这三个阶段就够了：

有序发射

按程序顺序进入

乱序执行

RS 发挥作用

有序提交

ROB 发挥作用

RS 让 CPU 跑得快，ROB 让 CPU 在跑得快的同时仍然保证程序的正确性。
