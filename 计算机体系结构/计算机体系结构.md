# 计算机系统结构基础
## 性能
**性能的最本质定义：完成一个任务所需的时间，主要用执行时间 ExeTime 表示。**

**基本概念：**

1、MIPS: Million Instructions Per Second $ \frac{InstCnt}{ExeTime\times 10^6} $

2、CPI：Cycles per Instruction $ \frac{Clycles}{InstCnt} $

3、CPU Time：一个应用程序执行过程中的 CPU 的使用时间

$ \begin{align}
CpuTime &= CycleTime*CPI*InstCnt  = \frac{CPI*I}{f} = CycleTime*\sum^n_{j=1} (CPI_j*I_j)\\
CPI &= \sum^n_{j=1} (CPI_j*F_j) \\
F_j &= \frac{I_j}{InstCnt}
\end{align} $

4、Amdahl 定律：通过使用某种优化所获得的性能提高，受可使用这种优化加速的执行时间占总执行时间的比例。

$ \begin{align}
ExeTime_{new} &= ExeTime_{old}*(1-f_{enhanced}+\frac{f_{enhanced}}{Speedup_{enhanced}})\\
Speedup_{overall} &= \frac{ExeTime_{old}}{ExeTime_{new}} \\
\end{align} $

理解：系统加速比=1/[(1-可改进比例)+可改进比例/部件加速比]

**性能评价：**

1. 基准测试程序
2. 归一化：将不同计算机的执行时间与一台参考计算机想比较后得到一个相对值（比值）
3. 几何平均

# 二进制与逻辑电路
## 数的表示
### 原码 
$ A=a_{n-1}a_{n-1}\cdots a_1 a_0 $

最高位 a[n-1] 位符号位

+ 0: $ +a_{n-1}\cdots a_1 a_0 $
+ 1: $ -a_{n-1}\cdots a_1 a_0 $

<font style="background-color:#FBDE28;">范围：</font>$ [-2^{n-1}+1, 2^{n-1}-1] $<font style="background-color:#FBDE28;">，有两个 0，+0 和-0</font>

### 补码
$ A=a_{n-1}a_{n-1}\cdots a_1 a_0 $，数值$ -2^{n-1}a_{n-1}+2^{n-2}a_{n-2}+\cdots+2a_{1}+2^0a_0 $，类似于带符号的取模运算，可以把减法转换成加法。

最高位 a[n-1] 位符号位

+ 0: 补码=原码
+ 1：补码表示的值为：-1 * 其余位取反加1 表示的值
    - 补码=(原码最高位，原码其余位**取反加 1**)
    - 原码=(补码最高位，补码其余位**取反加 1**)

<font style="background-color:#FBDE28;">范围：</font>$ [-2^{n-1}, 2^{n-1}-1] $<font style="background-color:#FBDE28;">，有一个 0，+0</font>

### 移码
$ A=a_{n-1}a_{n-1}\cdots a_1 a_0 $，数值为 $ 2^{n-1}a_{n-1}+2^{n-2}a_{n-2}+\cdots+2a_{1}+2^0a_0-移码值 $

移码值一般为$ 01\cdots11b $，即 $ 2^{n-1}-1 $。

移码值对应的二进制，表示 0。

<font style="background-color:#FBDE28;">范围：</font>$ [-2^{n-1}+1, 2^{n-1}] $<font style="background-color:#FBDE28;">，有一个 0，0</font>

### 浮点
(符号位, 阶码，尾数)，数值为$ 二进制表示=\pm 1.尾数b\times2^{阶码-移码值} $

+ 符号位 **s**：0 正 1 负
+ 阶码 **e**：移码表示，范围为$ [-(2^{n-1}-1)+1, 2^{n-1}-1] $，共$ 2^n-2 $个阶码，全 1 和全 0 另有表示。含义上，设值为 x，则表示 $ 2^x $
+ 尾数 **f**：二进制表示，表示该浮点数小数点后的数值，小数点前默认为 1b
+ 精度
    - 单精度：32=(1, 8, 23)
    - 双精度：64=(1, 11, 52)
    - 扩展单精度
    - 扩展双精度

:::tips
特殊情况

+ 阶码非全 0 全 1：规格化数$ \pm 1.尾数b \times 2^{阶码-127} $
+ 阶码全 0
    - f 全 0：$ \pm 0 $
    - f 不为 0：非规格化数$ \pm 0.尾数b \times 2^{-126} $，填补最小规格化数和 0 之间的一段空隙
+ 阶码全 1
    - f 全 0：$ \pm \infty $
    - f 不为 0：正为 Quiet NaN，运算结果仍为Quiet NaN；负数为 Signaling NaN，运算例外。

:::

## 逻辑电路
1、组合逻辑电路：输出 = f(输入)，当拍拿到结果

MOS 管表示组合逻辑电路：

1. NMOS 组成正逻辑（串与并或），PMOS 组成反逻辑（串或并与），最后再把正反逻辑串联。
2. 设计 CMOS 电路时最好用非、与非、或非来组成需要的逻辑  
~(A&B|C&D)：大结构为非，A&B|C&D 表示 NMOS，(~A|~B)&(~C|~D) 表示 PMOS  
A&B|C&D：
    1. 纯基本电路：改为~(~(A&B)&~(C&D)), 第一级 X1=~(A&B), X2=~(C&D)，第二级 Y=~(X1&X2) 
    2. （更简单，不容易出错）复合电路：改为~(~(A&B|C&D)), 第一级 X=~(A&B|C&D)，第二级 Y=~X



2、时序逻辑电路：输出=f(状态，输入)，下拍拿到结果，状态为存储单元的各个状态。

类型：

+ 同步时序电路：所有存储单元的变化由时钟统一触发 --> 需要设计时钟树来驱动这么多的触发器，时钟树每拍都在变化导致功耗很大
+ 异步时序电路：不使用是时钟来统一同步，设计难度大，功耗低

核心：数据存储单元

1. RS 触发器，R:reset，S:set  
RS触发器与组合逻辑的根本不同是在(R,S)的值从(0,1)或(1,0)变成(1,1)时能够保持输出值的状态不变,从⽽实现数据的存储。  
<img src="https://cdn.nlark.com/yuque/0/2024/png/12979548/1704735416242-034565db-cdf8-49f5-91d0-35c0b2900530.png" width="337" alt="" title="" crop="0,0,1,1" id="u4c14769a" class="ne-image">
2. D 锁存器和 D 触发器：  
D 锁存器：RS 触发器前面加两个与非门，用时钟 C 控制 D 输入  
	基本原理：由时钟 C 的电平控制  
	C=0, R 和 S 均为 1，相当于保持状态  
	C=1, 输出等于输入 D，相当于直通状态  
D 触发器：两个 D 锁存器串联  
	触发器的根本原理：通过时钟跳沿锁存数据  
	C=1，第一个直通，第二个保持  
	C=0，第一个保持，第二个直通  
	C=1->0（负时钟上升沿，正时钟下降沿），把 D 值锁存在第一个

## 时序电路延迟
1. 为了把 D 的值通过时钟沿锁存起来，要求<font style="color:#DF2A3F;">在时钟 C 变化之前的一定时间内 D 不能变</font>,这个时间叫做建⽴时间(setup time)。
2. <font style="color:#DF2A3F;">在时钟 C 变化之后的一定时间内 D 也不能变</font>，才能让第一个锁存器锁存到正确的值，这就是保持时间(hold time)。
3. <font style="color:#DF2A3F;">在时钟 C 变化之后 C 到 Q 端跟更新数据</font>的时间，为 Clock-to-Q 时间。

触发器延迟=建立时间 + _Clock-to-Q _时间

## CMOS 电路延迟
延迟原因：P 管和 N 管导通时源漏之间存在电阻，栅极和地之间存在寄生电容，故 CMOS 晶体管工作时输入和输出存在延迟。

构建方法：需要根据单元的电路结构构件每个单元的延迟模型（分单元构建）

+ **<font style="color:#DF2A3F;background-color:#FBDE28;">该单元延迟=该级本身延迟+该级的单位负载延迟*(该级输出/下一级输入负载+该级与下一级连线负载)</font>**  
其中：单元延迟=本身延迟+负载延迟，负载延迟=下一级负载+连线延迟  
负载延迟与该单元负载相关，负载的单位 fF(feto-Farad，读 fe-fa)，每负载延迟的单位 ns/fF。

## Verilog
重点理解：

1. verilog 是构件数字电路，逻辑通电时，为并行执行
2. for 语句会导致硬件上有多个硬件模块，⽽不是单个硬件模块多次执⾏某个功能

重点语法：

```verilog

// 2. 时序逻辑
// 阻塞赋值：阻塞赋值语句是在这句之后所有语句执行之前执行的，即后边的语句必须在这句执行完毕才能执行，所以称为阻塞，实际上就是顺序执行。
// 非阻塞赋值：非阻塞赋值就是与后边相关语句同时执行，即就是并行执行。
// 所以一般时序电路使用非阻塞赋值，组合电路使用阻塞赋值；
always @(posedge clock) begin

    c = 1;
```

# 指令系统结构
## 指令分类
指令使用数据的方式：

+ 堆栈型：默认操作数均在栈顶
+ 累加器型：一个操作数来自累加器，另一个由指令指定
+ 寄存器型
    - 寄存器-寄存器型：操作数均为寄存器（常用：访问快（CPU 与内存的剪刀差），容易判断相关性）
    - 寄存器-存储器型：操作数为寄存器或存储器

## 指令系统组成
1. 操作数
    1. 数据类型
    2. 访存地址
        1. 访问长度：字、半字、字、双字
        2. 是否支持不对齐访问：不对齐访问可能需要访问 2 次 cache 或内存
        3. 大尾端和小尾端：前者最低位最高字节，后者最低位在字节 0；
    3. 寻址方式
        1. 常用：偏移量寻址（Rx+Offset）、立即数寻址，寄存器寻址
2. 操作码：功能分类
    1. 运算指令：加减乘除、移位、逻辑运算；定点运算、浮点运算
    2. 访存指令
    3. 转移指令
        1. 分类：条件转移、无条件转移、过程调用和过程返回
    4. 系统管理指令：TLB 管理、cache 管理和例外处理
    5. 其他杂项指令：陷阱 trap，断点 breakpoint，不同寄存器组的数据传输等
3. 指令编码
    1. 定长
    2. 变长

## 原子指令🔴💻
LL/Load Linked：LL 指令从内存中取数并置系统中 LLbit 位为1。当 LLbit 为 1 时,处理器检查相应单元是否被修改，相应单元被修改或处理器执⾏了 ERET 操作，则将 LLbit 位置 0。

SC/Store Conditional：执⾏ SC 时,若 LLbit 为1，则存数成功，⽬标奇存器的值变为 1,否则存数不成功,⽬标寄存器的值变为 0。

核心思想：从内存中取值并对该值进⾏修改再写回内存的过程中，其他操作不能改变内存中 的值,从⽽保证本次操作的原⼦性。

```verilog
L1:	LL R1, 0(R3)
  	ADDIU R2, R1, R1
		SC R2, 0(R3)
  	BEQ R2, 0, L1
  	NOP
```



## 非对齐访存指令
小尾端：左高右低

大尾端：左低右高

+ LWL 指令：**取低补高**，取访存地址所在的字并把从字开始到访存地址的字节拼接到⽬ 标寄存器的<font style="color:#DF2A3F;">左边</font>(例如，如果访存地址为6,则取4~7字节所在的宇,并把 4~6 字节拼接到 ⽬标寄存器的⾼24位);
+ LWR 指令：**取高补低**，取访存地址所在的字并把从访存地址开始到字结束的字节拼接到⽬标寄存器的<font style="color:#DF2A3F;">右边</font>(例如，如果访存地址为 6,则取4~7字节所在的字，并把6~7字节拼接到⽬标寄存器的低 16位）。

结合 LWL 和 LWR 实现跨行或跨字的拼接取数，如取内存单元 101～104 中的 4 个字节到 R2，有：

LWR R2，101

LWL R2，104

## 相关性
指令相关->指令序关系

1. 数据相关：两条指令访问同一寄存器或内存单元，且至少有一条指令写该寄存器或内存单元，则二者存在数据相关  
5 级顺序流水线中，只有 RAW 引起流水线冲突。  
乱序执行流水线中，三者都可能导致流水线冲突。  
冲突会引起流水线阻塞，阻塞会降低流水线效率。
    1. RAW：真相关
    2. WAW：输出相关（假相关/名字相关）
    3. WAR：逆相关（假相关/名字相关）
2. 控制相关：两条指令中一条是转移指令，且另外一条指令是否被执行取决于该转移指令的执行结果，则二者存在控制相关
3. 结构相关：两条指令使用同一个功能部件，则二者存在结构相关



+ 假相关可以通过寄存器重命名解决
+ 转移指令在 ID 进行转移判断，设置转移指令延迟槽，可以避免控制相关引起的流水线阻塞。  
注意：延迟槽不依赖于转移条件执行。

指令调度技术：不影响程序正确性的前提下，通过<font style="color:#DF2A3F;">改变指令的执行次序</font>来<font style="color:#DF2A3F;">避免由于指令相关引起流水线阻塞</font>。

+ 静态调度：程序员/编译器<font style="color:#DF2A3F;">在程序执行前</font>进行的指令调度
+ 动态调度：硬件<font style="color:#DF2A3F;">在程序执行过程中</font>自动进行的指令调度

优缺点：

+ 软件调度的范围大，可以在上万条指令的范围内进行调度；硬件一般只能在百条指令范围内进行调度
+ 硬件调度可以掌握一些软件编译时还不明确的相关性信息，尤其是对访存相关以及控制相关，进行更细致的调度
+ 软件调度需要针对具体的流水线结构设计，硬件调度可减少程序性能对机器的依赖

**需要基于具体的处理器架构分析指令调度，因为：**

1. 相关不一定引起阻塞，只要隔开足够远
2. 在一个流水线上引起阻塞，在另一个流水线上不一定引起阻塞，所以编译 优化与机器有关

所以指令调度题一定要认真看题干给的处理器架构。



## 软件/静态调度技术
循环代码分为 2 个部分，运算部分和控制部分。

### 循环展开与重命名
步骤：

1. 循环展开：答题时一般按照抵消 stall 的最少次数 n 展开。展开 n 次，指<font style="color:#DF2A3F;">罗列 n 次循环的运算部分</font>消除和减少循环开销。展开后，注意<font style="color:#DF2A3F;">循环的（条件）控制部分</font>的数字变化。
2. 寄存器重命名（软件层面）：答题时一般重命名每个循环运算部分的寄存器
3. 改变指令次序
    1. 消除数据相关：一般先集中处理 load 指令，再集中处理运算指令，最后处理 store 指令。
    2. 充分利用延迟槽：用一条转移无关指令（一般是 store 指令，需要<font style="color:#DF2A3F;">注意地址偏移量的变化</font>）替换掉 NOP 延迟槽

如果总循环次数 N 不是展开次数 n 的倍数，最后 N%n 轮需要特殊处理。



缺点：寄存器重命名需要更多的寄存器；代码膨胀，ICache 缺失率可能增大了；有些循环不好展开，如循环次数不定的循环。

### 软件流水
> 考点习题 5.2，课堂在第 8 章讲解。
>
> 学习参考：[软件流水在干嘛（转）-CSDN博客](https://blog.csdn.net/diyinqian/article/details/86360396)

## 硬件/动态调度技术
基本原理：前面的指令由于相关而阻塞时，不阻塞后面不相关的指令。

### 保留站
译码 --> 发射和读操作数

+ 发射：指令译码，检查结构相关
+ 读操作数：如果操作数准备好就读数，否则在<font style="color:#DF2A3F;">保留站或发射队列</font>等待 --> 只要没有相关性就可执行

<font style="background-color:#FBDE28;">意义：乱序执行的起始点。</font>

### 寄存器重命名
> 软件重命名，会改变指令编码，使用的仍然是程序员可见的逻辑寄存器。
>
> 硬件重命名，逻辑寄存器映射到处理器内部的硬件寄存器，其对程序员不可见。
>

动态执行，会出现 WAW 和 WAR 的名字相关。



解决方案一：记录并等待 --> Scoreboard 

基本思想：

+ WAR 时，在 R 之前，不能 W 到寄存器堆；
+ WAW 时，在 W1 之前，不能 W2 到寄存器堆

缺点：必须保证 WAR 和 WAW 的串行次序，是假相关的寄存器使用成为阻塞瓶颈。



解决方案二：硬件寄存器重命名 --> Tomasulo 算法

基本思想：记录需要数据的源头：1、源操作数依赖前面哪条指令的目标结果；2、寄存器写数据依赖前面哪条指令的目标结果

缺点：结果总线成为瓶颈，多条结果总线增加硬件复杂度。

## Tomasulo 算法
### 算法结构
1. Busy 位没有显示表示，这里指保留站是否满。
2. 保留站的作用：（1）乱序执行的起点；（2）重命名寄存器+缓存源操作数

<img src="https://cdn.nlark.com/yuque/0/2024/png/12979548/1704903267997-8c89c173-b244-4c04-88d1-30c566c71aa8.png" width="877" alt="" title="" crop="0,0,1,1" id="EKNBj" class="ne-image">



### 步骤
+ 发射：把操作队列的指令根据操作类型送到保留站（如果保留站有空），发射过程中读寄存器的值和结果状态域。
    - 更新保留站 entry，更新寄存器堆 entry
    - 写题时注意<font style="color:#DF2A3F;">保留站 Q 位和寄存器堆 state 位</font>对应都是<font style="color:#DF2A3F;">保留站号，前者无等待为 0，后者无等待为空  
</font>**<font style="color:#000000;">保留站 Q 位看寄存器堆 state 位更新，寄存器堆 state 位看保留站号更新</font>**<font style="color:#000000;">，故二者数据存的都是保留站号，但更新依赖方向不同。</font>
+ 执行：如果所需的操作数都准备好，则执行，否则侦听结果总线并接收结果总线的值。
+ 写回：把结果送到结果总线，释放保留站。
    - 结果总线同时更新保留站 entry 和寄存器堆 entry

### 更新顺序
1. 写回（结果总线更新时）：移除保留站指令记录，更新等待该保留站记录号的保留站数据和寄存器堆数据

## 精确例外处理：ROB
### 基本原理
乱序提交会导致非精确例外：在乱序执行时，前面的指令发生例外时，后面的指令已经执行完并修改了寄存器或存储单元。

记分板和 Tomasulo 都可能发生非精确例外。

:::tips
原理：在某些情况不确定的情况下先执行，但留有反悔的余地，如 ROB、推测执行

:::

ROB 基本原理：用缓冲器来临时保存执行结果，当前面所有指令执行完后 , 再把保存在缓冲器中的结果写回到寄存器或存储器。

### 算法结构
+ 阶段：增加提交（Commit）阶段，用于写回寄存器或存储器。
+ 缓冲器保存内容：目标地址（存数地址或寄存器号）、 值、 操作类型。
+ 寄存器堆内容：state 为最新结果指令的 ROB 号<font style="color:#8A8F8D;">（因为后续指令可能从 ROB 中读数，故使用ROB号作为重命名号->原来使用的保留站号）</font>
+ 保留站内容
    - 新增指令 ROB 号，用于结果总线更新时，同时更新指令对应的 ROB 数据和保留站数据。
    - Q 位：源操作数等待的 ROB 号（根据**<font style="color:#000000;">寄存器堆 state 位</font>**<font style="color:#000000;">设置</font>）

|  | 无 ROB | 有 ROB |
| --- | --- | --- |
| 寄存器堆 state 位 | 保留站号 | ROB 号 |
| 保留站 Q 位 | 保留站号 | ROB 号 |
| 保留站 ROB 号位 | - | ROB 号 |
| ROB addr 位 | - | 寄存器号或目标地址 |


### 步骤
+ 发射：把操作队列的指令根据操作类型<font style="color:#DF2A3F;">送到保留站</font>（<font style="color:#DF2A3F;">如果保留站以及ROB 有空</font>），并在<font style="color:#DF2A3F;">ROB中指定一项</font>作为临时保存该指令结果之用；发射过程中<font style="color:#DF2A3F;">读寄存器的值和结果状态域</font>，如果结果状态域指出结果寄存器已被重命名到ROB，则读ROB
+ 执行：如果所需的操作数都准备好，则执行，否则根据结果ROB号侦听结果总线并接收结果总线的值
+ 写回：把结果送到结果总线，释放保留站；<font style="color:#DF2A3F;">ROB根据结果总线修改相应项</font>
+ 提交：如果队列中<font style="color:#DF2A3F;">第一条指令</font>的结果已经<font style="color:#DF2A3F;">写回且没有发生例外</font>，把该指令的结果从ROB写回到寄存器或存储器，释放ROB的相应项。如果<font style="color:#DF2A3F;">队列头的指令发生了例外或是猜测错误的转移指令，清除操作队列以及ROB等</font>

### 更新顺序
写回和提交至少两拍

1. 写回（结果总线更新时）： 移除保留站指令记录，更新该指令 ROB 号对应的 ROB 数据，更新等待该指令 ROB 号的保留站数据。
2. 提交： 移除 ROB 指令记录，<font style="color:#DF2A3F;">更新寄存器数据</font><font style="color:#000000;">（无论 state 对不对号都要更新）</font>，如果提交 ROB 号和 state 位想等，则清除 state 位。
3. 发生例外时，等待例外 ROB 项前面的项全部提交，清空 ROB 表，并处理该例外

## 总结
主要数据结构：

+ 保留站（发射队列）把有序变成乱序，临时存指令
+ 重命名寄存器用于保存未提交的临时结果，临时存数据
+ ROB把乱序重新变成有序

物理寄存器的用途：

+ 源操作数：**复用不分配**，复用逻辑寄存器（m 个）和标识了目标操作数的重命名物理寄存器。
+ 目标操作数：需要分配重命名物理寄存器，直到提交后释放。满负荷时有 n*t2 条指令，故需要分配 n*t2 个物理寄存器。
+ 逻辑寄存器：这里物理寄存器应该是逻辑寄存器和重命名寄存器共用，故需要单独留 m 个，会在源操作数时使用。

<details class="lake-collapse"><summary id="u9606e808"><span class="ne-text">题解</span></summary><p id="ua24fb7d0" class="ne-p"><span class="ne-text">物理寄存器个数应至少为 n×t2+m 才能让流水线满负荷工作。 </span></p><p id="u8707d22e" class="ne-p"><span class="ne-text">每条指令在重命名的时候需要占用一个物理寄存器，每拍 n 条指令发射，则需要占用 n 个物理寄存器，被重命名的物理寄存器只有在提交的时候，并且不是当前逻辑寄存器的时候，才被释放。从重命名到提交共有 t2 拍，当流水线满负荷工作，流水线占用了 n*t2 个物理寄存器，另外逻辑寄存器数目为 m 个，因此共需要物理寄存器的个数为 n*t2+m。</span></p></details>

## 转移预测概念
1. 预测阶段：取指（仅根据 PC）/译码（PC+op 类型）/取指基于 PC 预测，译码基于译码信息再预测以及时纠正取指时的预测。（在译码级预测，好处是确定是转移指令，精度提高；坏处是浪费了 1 拍的取指槽，4 发射就浪费了 4 条指令的取指带宽。）
    - 预测内容：方向、目标地址等
    - 预测关键：如何记录转移历史、记录那些转移历史，记录多少转移历史、什么时候更新转移历史
2. 执行预测：译码/执行
3. 取消预测：
    1. 在执行后，取消部分指令
    2. 判断指令流水线中每一条指令与错误预测的转移指令的先后关系，取消在其之后的指令
    3. 注意转移预测未纠正前，不执行 I/O 指令，别面修改 I/O 控制器状态



性能评估：预测精度、正确预测的延迟、转移取消的延迟

⼀个⾼性能转移预测机制需要包括如下特征：

+ 早预测：减少预测延迟槽(如⽤根据 PC 预测的 BTB/BTAC 等机制)；
+ 早纠错：在执⾏阶段尽早确定转移结果,降低错误预测的开销； 
+ 快纠错：在转移预测错误时要有⾼效的流⽔线刷新机制;
+ 高精度：具有⾼预测精度的转移预测机制等。

## 加法器
### 串行进位
n 位串行进位加法器：

+ $ C_{n} $计算需要 $ 2n $ 级门延迟（延迟随位数增长线性增长）
    - 2 是 ai，bi, ci 生成 ci+1 的延迟
+ $ S_{n-1} $计算需要 $ 2(n-1)+3 $ 级门延迟，只要$ C_{n-1} $到位，即可计算
    - 最后一个 3 是 ai, bi, ci 生成 si 的延迟

### 块内并行，块间串行
块内 x 位并行进位加法器：块内并行，块间串行

+ $ C_{n} $计算需要 $ 2+2\cdot\frac{n}{x} $ 级门延迟（还是线性增长）
    - 第一个 2 是 ai, bi 生成 pi, gi 的延迟，第二个 2 是 pi,gi 生成 c4 的延迟
    - n/x 是指 n 位，一块 x 位，共 n/x 块

## Wallace Tree
多个数相加（32 位乘法，通过 2 位 1 乘的 Booth 得到 16 个 64bit 的部分积）

+ 二叉树状结构：16 个 64bit 需要 5 次串行加法（16->8->4->2->1），共 5*15=75 级门延迟。
+ 华莱士树：把 n 个数相加规约成两个数相加。16 个 64bit，即 64 个 WT 并行执行，每 bit 需要 6 层 WT 完成 16 个 bit 的串行执行，最后一个 64bit 加法，共 6*3+15=33 级门延迟。



进位要求：

+ 进位输入信号必须接到进位输出该信号层次的**下一层或更高**  
凡是由全加器的进位生成的部分连接到**下一级**时要链接到**下一层**的高位
+ 放图理解：
    - 下一级（X 位，X 个 WT 视角）：从右到左看，N 个 X 位数的加法，从右到左，分别是第 0，1，...，x-1 位的 WT

## 共享存储系统之指令相关
> Lamport 在 1979 年提出了顺序⼀致性( Sequential Consistency)模型，这⼀模型后来被普遍 认为是判断⼀个并⾏执⾏是否正确的标准。该模型指出如果在共享存储系统中多机并⾏执 ⾏程序的效果等于把每⼀个处理器所执⾏的指令流按某种⽅式顺序地交织在⼀起在单机上 执⾏的结果,则该共享存储系统的顺序是⼀致的。
>

定义：

+ ⼀个进程P是⼀个序结构`＜V(P),Po(P)>`,其中,`V(P)`是访存指令的集合,`Po(P)`是`V(P)`上 的⼀个全序关系。
+ 把程序 PRG 中冲突访问对的集合记为`C (PRG)`
+ 在程序 PRG 中,对冲突访问对集` C(PRG) `的任 意⼀个**<font style="color:#DF2A3F;">⽆圈定序</font>**称为程序 PRG 的⼀个执⾏，记为 `E(PRG)`

根据顺序⼀致性的要求,⼀个并⾏程序执⾏正确的条件是其结果等于该程序的⼀个正 确的串⾏执⾏的结果,⽽执⾏本⾝不必串⾏。

## Cache 一致性协议🔴
cache ⼀致性协议是把某个处理器新写的值传播给其他处理器以确保所有处理器看到 ⼀致的共享存储内容的⼀种机制。

+ 如何传播新值
    - 写使⽆效：当根据⼀致性要求 要把⼀个处理器对某⼀单元所写的值传播给其他处理器时，就使其他处理器中该单元的备 份⽆效;其他处理器随后要⽤到该单元时,再获得该单元的新值 --> 缺点：乒乓效应
    - 写更新：当根据 ⼀致性要求要把⼀个处理器对某⼀单元所写的值传播给其他处理器时，就把该单元的新值 传播给所有拥有该单元备份的处理器对相应的备份进⾏更新 --> 频繁更新
+ 谁可以产⽣新值
    - 单写协议：每次只允许⼀个处理器写某⼀共享单位。 --> 缺点：假共享严重
    - 多写协议：它允许多个处理器同时读或 写分布在同⼀个共享单位的不同单元，⼀个处理器对某⼀单元的修改对其他处理器来说可 以暂时不可见，直到同步操作时才把新值传播给其他处理器。程序员必须保证在同⼀个同 ⽣区间内不会有对同⼀单元的冲突访问。
+ 什么时候传播新值
    - 及时传播：一个处理 器更新某⼀共享块时，及时向其他处理器发出写⽆效或写更新信号
    - 延时传播：针对软件共享存储系统通信开销⼤的缺点提出来的，如急切更新⼀致性和懒惰更新⼀致性。
+ 新值将会传播给谁
    - 侦听协议：当⼀个处理器对共享变量的访问 不再 cache 命中或可能引起数据不⼀致时，它就把这⼀事件⼴播到所有处理器。
    - ⽬录协议：为每⼀存储 ⾏维持⼆⽬录项,该⽬录项记录所有当前持有此⾏备份的处理器号以及此⾏是否已被改写 等信息。当⼀个处理器欲往某⼀存储⾏写数且可能引起数据不⼀致时，它就根据⽬录的内 容只向持有此⾏的备份的那些处理器发出写使⽆效/写更新信号,从⽽避免了⼴播。

```verilog
module alu_module(
    input [ 3:0] aluop,
    input [31:0] in1,
    input [31:0] in2,
    output [31:0] out
);
  wire slt_res;
  assign slt_res = (in1[31] && !in2[31]) & 1’b1 |
    (in1[31] && in2[31] ) & (in1<in2) |
    (!in1[31] && !in2[31]) & (in1<in2) |
    (!in1[31] && in2[31]) & 1’b0; 
  assign out = 
  {32{aluop==4’b0000}} & (in1+in2) |
  {32{aluop==4’b0001}} & (in1-in2) |
  {32{aluop==4’b0010}} & {31'b0, slt_res} |
  {32{aluop==4’b0011}} & {31'b0, in1<in2} |
  {32{aluop==4’b0100}} & (in1&in2) |
  {32{aluop==4’b0101}} & (in1|in2) |
  {32{aluop==4’b0110}} & (in1^in2) |
  {32{aluop==4’b0111}} & ~(in1|in2) |
  {32{aluop==4’b1000}} & (in1<<in2) |
  {32{aluop==4’b1010}} & (in1>>in2) |
  {32{aluop==4’b1011}} & ($signed(in1)>>>in2); //verilog2001 中算术右移的新表达方式
```

```verilog
module add16(a, b, cin, out, cout);
input [15:0] a;
input [15:0] b;
input cin;
output [15:0] out;
output cout;

C4 C0_3(.p(p[3:0]),.g(g[3:0]),.cin(c[0]),.P(P[0]),.G(G[0]),.cout(c[3:1]));
C4 C4_7(.p(p[7:4]),.g(g[7:4]),.cin(c[4]),.P(P[1]),.G(G[1]),.cout(c[7:5]));
C4 C8_11(.p(p[11:8]),.g(g[11:8]),.cin(c[8]),.P(P[2]),.G(G[2]),.cout(c[11:9]));
C4 C12_15(.p(p[15:12]),.g(g[15:12]),.cin(c[12]),.P(P[3]),.G(G[3]),.cout(c[15:13]));
C4 C_INTER(.p(P),.G(G),.cin(c[0]),.P(),.G(),.cout({c[12],c[8],c[4]}));
assign cout = (a[15]&b[15]) | (a[15]&c[15]) | (b[15]&c[15]);
assign out = (~a&~b&c)|(~a&b&~c)|(a&~b&~c)|(a&b&c);
endmodule

module C4(p,g,cin,P,G,cout)
input [3:0] p, g;
input cin;
output P,G;
output [2:0] cout;
assign P=&p;
assign G=g[3]|(p[3]&g[2])|(p[3]&p[2]&g[1])|(p[3]&p[2]&p[1]&g[0]);
assign cout[0]=g[0]|(p[0]&cin);
assign cout[1]=g[1]|(p[1]&g[0])|(p[1]&p[0]&cin);
assign cout[2]=g[2]|(p[2]&g[1])|(p[2]&p[1]&g[0])|(p[2]&p[1]&p[0]&cin);
endmodule
```
